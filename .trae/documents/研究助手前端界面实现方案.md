# 研究助手前端界面实现方案

## Context（背景与目标）

当前项目是一个基于 LangGraph 的「研究助手」Agent 后端：

- 对外仅提供 `POST /research_assistant/ask`（[routes.py](file:///e:/learning_information/LLM/project/research_assistant/app/api/routes.py)），请求体为 `{user_id, session_id, question}`，一次性返回完整答案（非流式）。
- Agent 由 LLM + 两个工具（`knowledge_search` 本地知识库检索、`web_search` 联网搜索）组成，会话记忆通过 LangGraph `InMemorySaver` 按 `thread_id = session_id` 维护。
- 后端没有前端界面，也没有配置 CORS。

目标：在 `frontend/` 目录下新增一个现代化、清晰简约美观的聊天界面，并通过 FastAPI 同源托管，实现「一条命令启动即可在浏览器中使用」。

## 技术选型（已与用户确认）

| 决策项 | 选择 |
|---|---|
| 前端技术栈 | 原生 HTML / CSS / JS，零构建、零 Node 依赖 |
| 前后端集成 | FastAPI 直接托管静态文件（同源，无需 CORS） |
| 输出方式 | 保持现有非流式 `/ask`，后端接口不改动 |

## 文件结构

```
frontend/
  index.html     # 单页聊天界面骨架
  styles.css     # 现代化样式（CSS 变量、响应式、动画）
  app.js         # 会话管理与 /ask 调用逻辑
```

后端仅新增静态托管，不改动任何业务逻辑。

## 实现步骤

### 1. 新建 `frontend/index.html`

- 语义化结构：顶部 Header（应用标题 + 「新对话」按钮）、中部消息列表容器、底部输入区。
- 输入区：自适应 `textarea` + 发送按钮；空状态时展示引导文案与示例问题。
- 通过 `<link>` / `<script defer>` 引入同目录的 `styles.css` 与 `app.js`，不引入任何外部 CDN 依赖。

### 2. 新建 `frontend/styles.css`

- 使用 CSS 变量定义配色、圆角、阴影、间距，便于统一维护。
- 现代化视觉：干净的浅色主题、卡片式消息气泡（用户右侧 / 助手左侧）、柔和阴影与 8–12px 圆角、清晰的中文字体栈（系统字体，无外部字体依赖）、平滑的淡入/滑入过渡动画。
- 响应式：桌面居中限定最大宽度，窄屏自适应铺满。
- 加载态：请求进行中显示「正在思考」的灵动点动画，禁用发送按钮。

### 3. 新建 `frontend/app.js`

- **身份与会话**：
  - `user_id`：首次访问生成并存入 `localStorage`，长期复用。
  - `session_id`：每次「新对话」生成新的 UUID，作为 `thread_id` 传给后端，从而支持多轮上下文；存入 `sessionStorage` 以在刷新时保持当前会话。
- **发送逻辑**：`fetch('/research_assistant/ask', { method: 'POST', headers, body })`，同源相对路径，无需跨域配置。
- **渲染**：助手回答用 `white-space: pre-wrap` 保留换行；将回答中的 URL 自动转为可点击链接。
- **交互**：`Enter` 发送、`Shift+Enter` 换行；请求期间禁用输入与按钮，显示加载态；失败时以醒目样式提示并可重试。
- **「新对话」**：清空消息列表并重置 `session_id`。

### 4. 修改 `app/main.py` 挂载静态文件

- 引入 `from fastapi.staticfiles import StaticFiles` 与 `pathlib.Path`。
- 在**现有 `include_router(...)` 之后**追加：
  ```python
  app.mount(
      "/",
      StaticFiles(directory=Path(__file__).resolve().parent.parent / "frontend", html=True),
      name="frontend",
  )
  ```
- 关键点：
  - 使用基于 `__file__` 的绝对路径，避免受启动时工作目录影响。
  - 挂载顺序放在路由注册之后——Starlette 按注册顺序匹配，`/research_assistant/*` 与 `/docs` 等具体路由会先命中，根挂载仅兜底静态资源。
  - 同源访问使前端无需 CORS 中间件。

## 复用的现有能力

- 直接复用现有 `POST /research_assistant/ask` 接口与 [schemas.py](file:///e:/learning_information/LLM/project/research_assistant/app/api/schemas.py) 中定义的数据契约，前端字段与之严格对齐（`user_id` / `session_id` / `question` / `answer`）。
- `session_id` 直接作为 LangGraph 的 `thread_id`，复用后端已有的多轮会话记忆能力，无需改动 [agent_service.py](file:///e:/learning_information/LLM/project/research_assistant/app/services/agent_service.py)。

## 验证方式（端到端）

1. 启动服务（项目根目录）：
   ```bash
   uvicorn app.main:app --host 0.0.0.0 --port 8000
   ```
2. 浏览器访问 `http://localhost:8000/`，确认界面正常加载。
3. 发送知识库类问题（如「什么是贝叶斯公式？」）验证 `knowledge_search` 链路。
4. 发送实时类问题（如「给我找几篇近几年的多目标优化论文」）验证 `web_search` 链路。
5. 连续追问，确认多轮上下文（同一 `session_id`）生效；点击「新对话」后确认会话重置。
6. 打开浏览器控制台确认无报错；确认 `http://localhost:8000/docs` 仍可正常访问（验证挂载未影响 API 路由）。

## 明确不做的事项

- 不改造后端为流式（SSE）输出。
- 不引入 React/Vue、打包工具或前端依赖。
- 不新增 CORS 配置（同源托管已满足）。
